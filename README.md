# Page Tuner

A Chrome extension that reshapes pages you spend all day on. Each tweak is a **rule** you toggle
independently from the extension popup; every rule is off until you turn it on.

## Rules

### GitHub

| Rule | What it does |
| --- | --- |
| Auto review and collapse autogenerated files | Marks generated files (`Gemfile.lock`, `structure.sql`, `schema.graphql`, `*.generated.ts`, …) as viewed and collapses them. |
| Move out Compare and Open Pull Request buttons | Lifts the buttons hidden behind the branch page's "Contribute" dropdown into the page itself. |
| Mark file as viewed (Shift+Space) | Marks the diff under the cursor as viewed from the keyboard, with a hint on the target button. |
| Auto expand large diffs | Clicks "Load Diff" on large files that aren't autogenerated and aren't already reviewed. |
| Go to line in editor | Adds a button on every diff line that opens the file at that line in Cursor. Needs a repo → local path mapping, configured in the popup. |
| Copy file name from review threads | Copy button next to the file name in a review thread. |
| Copy comment link & path in review threads | Copies a comment's permalink, or the file path with its line number. |
| Approve & 👁 shortcuts next to Submit review | One-click approve, and a 👁 button that submits a comment review with the body `👁`. |

### Peakon

| Rule | What it does |
| --- | --- |
| Remember survey answers | Stores your answer per question and highlights it when the question comes round again. A badge in the bottom-right corner opens a panel listing which page selectors still match, what is on file for the question in front of you, and every answer stored so far. |

## Installing

1. `npm install`
2. `npm run build` (or `npm start` for a watching dev server)
3. Open `chrome://extensions/`, enable **Developer mode**, click **Load unpacked**, select `build/`.

After changing the code, rebuild and hit reload on the extension card. Content script changes also
need a refresh of the page you're testing on.

## How a rule is wired

A rule touches four places:

1. **`src/pages/Content/<rule-name>.ts`** — the behaviour, exported as an `inject*` or `wire*` function.
2. **`src/pages/Content/rule-definitions.ts`** — the rule's name and any config it needs (`specifics`).
3. **`src/pages/Content/index.tsx`** — an init function that checks the rule is enabled and the URL
   matches, then wires it up (usually via a `MutationObserver`, since GitHub renders late and remounts
   on client-side navigation).
4. **`src/pages/Popup/Popup.tsx`** — the toggle.

The background service worker (`src/pages/Background/index.js`) owns the rule state in
`chrome.storage.local`, reconciles it against `rule-definitions.ts` on install and update, and answers
`GET_RULES` messages.

## Testing

```
npm test           # jest, jsdom
npm run test:watch
```

Rules are tested against fixtures of GitHub's real DOM. Because that DOM is hashed CSS modules,
selectors match by prefix (`[class*="ReviewMenuButton-module__"]`) with a text-based fallback.

## Packing

```
NODE_ENV=production npm run build
```

Produces `build/` ready to load, plus a zip in `zip/`.
